# Домашнее задание 7. Java Collections

## Как запустить тесты

Нужны Java 17+ и Maven. Из корня проекта:

    mvn test

В IntelliJ IDEA: правая кнопка на папке `src/test/java`, затем Run 'All Tests'.

## Где что находится

Все классы лежат в `src/main/java/hometask7`, тесты в `src/test/java/hometask7`.

- Задание 1: `CustomList.java`, `CustomArrayList.java`; тесты в `CustomArrayListTest.java`.
- Задание 2: `CollectionPerformanceExperiment.java` (запускается через `main`).
- Задание 3: `Student.java`, `StudentRegistry.java`; тесты в `StudentRegistryTest.java`.

## Выводы

В ArrayList элементы лежат в одном массиве, поэтому доступ по индексу занимает O(1), а у LinkedList приходится идти по цепочке узлов от начала или конца, то есть O(n). Из-за этого доступ по индексу и вставка в середину у LinkedList оказались в десятки раз медленнее: основное время уходит на поиск позиции. Вставка и удаление в начале у ArrayList требуют сдвига всех остальных элементов, это O(n), а у LinkedList достаточно поменять пару ссылок, это O(1), поэтому здесь LinkedList быстрее. Добавление в конец у ArrayList в среднем тоже O(1), но иногда нужно создать новый массив и скопировать данные, а LinkedList при каждом добавлении создаёт новый узел-объект, и стоимость выделения памяти у него сопоставима. Элементы массива лежат рядом в памяти и хорошо подходят для кэша процессора, а узлы связного списка разбросаны по памяти, что замедляет обход. Вставка в середину у LinkedList всё равно проигрывает, потому что поиск середины стоит дороже, чем сдвиг половины массива, который выполняется быстрой системной копией. Вывод: ArrayList лучше при частом доступе по индексу и вставке в середину, LinkedList имеет смысл при частых вставках и удалениях в начале списка. Абсолютные числа зависят от компьютера и JVM, поэтому в тестах они не сравниваются.
